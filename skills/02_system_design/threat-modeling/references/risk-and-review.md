# 風險排序與模型審查

## 沒有組織尺度時的暫定方法

不用 CVSS 套算每個設計威脅，也不把低／中／高編碼當精確機率。以下只是討論尺度，正式排序依組織政策。

- 可能性高：入口可達、所需權限容易取得、攻擊條件直接且控制不足有證據。
- 可能性中：需特定帳號、條件或多步攻擊；仍具可行路徑。
- 可能性低：需難取得能力或特殊條件，且有可信控制證據；不能僅因沒見事故判低。
- 影響高：重大敏感資料、廣泛租戶、金流／核心營運、重大法規或安全後果。
- 影響中：有限資料／範圍、可復原的業務損失或部分服務中斷。
- 影響低：範圍小且後果有限，需解釋限制影響的機制。

可能性與影響各自附理由、來源及未知。高可能性＋高影響先處理；高影響但條件未知者優先蒐證，不能直接降為低。其他組合按業務情境排序並解釋，不宣稱這是標準矩陣。修復成本、時間與相依性另列為執行排序因素。

風險與證據信心不同：低信心可能意味優先確認，而非低嚴重度。防禦已存在時評估它實際阻斷的路徑；未驗證部署有效性時保留限制。

## 交付審查

| 檢查 | 可接受的證據／結果 |
|---|---|
| 範圍與版本 | 系統、環境、來源版本、變更範圍及限制明確；不把來源 repo 與部署環境混為一談 |
| 模型一致性 | 圖、元素表、資料流表與威脅引用 ID 一致；重要方向、敏感資料及邊界有表達 |
| 代碼中文對照（必要交付） | 已建立／更新可查閱的完整清單；每個實際 ID、分類組合、結果碼、重要名稱及縮寫均有本案中文說明及來源；前綴與符號讀法清楚，模型／成果入口／交付回覆附連結；無漏列、矛盾或以候選冒充核准 |
| 方法選擇 | 面向、維度、分類及評估層次分清；方法選擇有理由、來源與限制；適用隱私與業務面向未被 STRIDE 取代 |
| 覆蓋 | 關鍵資產與流程、跨權限流及適用面向已分析；未分析／未知項目顯示其影響 |
| 情境可操作 | 每筆威脅有能力、前提、路徑、違反規則、資產與後果；不是通用漏洞名詞 |
| 證據可信 | 可回查來源；宣稱、推論、靜態與執行驗證分開；未見控制不等於控制不存在 |
| 排序可解釋 | 尺度、理由、不確定性與業務衝擊清楚；成本不掩蓋風險 |
| 處置完整 | 高優先項有處置／待決事項、負責角色及期限或未知；不能只寫最佳實務 |
| 追溯 | TM → REQ／候選需求 → CTRL → 工作／實作 → TEST／證據可追查；接受／移除有決策鏈 |
| 驗證誠實 | 設計、存在、已執行、通過／失敗分開；預期剩餘風險不冒充已驗證 |
| 決策有效 | 接受風險有正式紀錄，或清楚標待決；沒有代填核准或自動解鎖 |
| 更新可維護 | 變更／退役保留 ID 與理由，接受風險與驗證是否仍適用已重新檢視 |

結論：通過表示在已述範圍與限制內滿足模型交付要求；待修正列出具體缺口；證據不足指出缺哪些證據與取得方式。關鍵授權、資料流或高影響決策未知，不能用平均分數掩蓋。專案階段是否放行仍依原有規則與責任人決策，本 Skill 不增加或覆寫全域 gate。
