# 分析提示：按情境選用

這是防止遺漏的提示，不是每個系統都必須產生相同威脅清單。從入口、資料流、控制點與業務規則推導情境；不適用需寫理由。

## STRIDE

| 類別 | 檢視問題 | 注意點 |
|---|---|---|
| S 身分冒用 | 使用者、工作負載、裝置或第三方身分能否被偽造、竊取、重放？ | 檢查 Token 受眾、用途、期限、撤銷、帳號復原及服務身分 |
| T 資料竄改 | 請求、訊息、資料、設定或成品能否被未授權修改？ | 檢查完整性、簽章、重放及伺服器端可信資料來源 |
| R 否認行為 | 關鍵行為能否被追查，證據能否被刪改？ | 記錄完整性、時間與主體關聯；更多日誌不一定更安全 |
| I 資訊洩漏 | 是否能越權讀取、推知或外傳敏感資訊？ | 錯誤訊息、快取、備份、日誌、分析事件及資料匯出 |
| D 阻斷服務 | 是否能耗盡計算、儲存、配額或昂貴第三方呼叫？ | 限流粒度、資源上限、佇列壅塞與復原；含費用耗盡 |
| E 權限提升 | 是否能取得更高角色，或跨越帳戶／租戶權限？ | 管理介面、物件授權、服務帳號、權限變更後的舊工作階段 |

## 依系統特性加深

| 適用面向 | 分析提示 |
|---|---|
| 業務濫用 | 支付、退款、審核、優惠或庫存流程能否跳步、重複、競態、重放？狀態轉換是否在伺服器強制？冪等鍵是否綁主體／操作，且原子性正確？ |
| 隱私 | 資料是否過量蒐集、超出原用途、保留過久？合法存取仍可能跨資料集識別或追蹤個人。需要時採 LINDDUN；資訊洩漏分類不涵蓋全部隱私傷害。 |
| 多租戶與身分聯邦 | 租戶 ID 是否由可信主體決定？背景工作、快取鍵、搜尋、匯出是否同樣隔離？SSO 信任、委派權限與帳號復原是否可繞過正常驗證？ |
| 雲端／部署 | 分清控制面與資料面、供應商與客戶責任。查 IAM、公開存取、metadata、工作負載身分、管理介面及環境隔離；設定文件只代表宣稱／配置，部署現況可能未知。 |
| 供應鏈與 CI/CD | 套件、更新、建置成品或流水線能否被置換？外部 PR／不可信輸入是否接觸有權限的 runner、發布憑證與成品？簽章驗證在何處強制？ |
| 維運與復原 | 告警可否被規避？管理員、備份及日誌是否共享故障／權限域？復原、撤銷及事件隔離能否在受攻擊時生效？備份存在不等於已驗證可還原。 |
| API／第三方事件 | Webhook 是否驗證來源、內容、時效與重放？SSRF、回呼目的地、依賴失效時的授權行為是否受限制？ |
| AI／Agent（有此元件才適用） | 把使用者輸入、RAG 文件、工具回應視為不可信資料。提示注入能否轉成工具操作或外傳？檢查工具實際權限、資料隔離、出站限制、人工關卡及資源配額；模型拒答不是授權控制。 |

## 一筆可操作的情境

TM-001：登入的一般會員透過 F-01 提交其他會員的訂單 ID，在 P-01 未檢查物件歸屬的假設下，跨 TB-01 讀取 DS-01 的姓名與地址。入口：訂單 API；能力：一般帳號；影響：他人個資曝光。來源不足時標候選，不寫成已確認漏洞。

控制：P-01 使用可信登入主體逐次判斷訂單歸屬，拒絕跨帳戶請求且不回傳敏感內容。
驗證：兩個測試帳號與各自訂單，A 讀取 B 的訂單應被拒絕且回應不含 B 資料；A 讀取自身訂單應成功。只有存在測試執行證據才標通過。
