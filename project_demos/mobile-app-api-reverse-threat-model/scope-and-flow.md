# 範圍與流程

## 目的

示範新手如何從既有 API 文件與程式行為線索，整理行動 App 授權、權杖換發與網站工作階段建立流程，再以 DFD 和 STRIDE 找出需確認的安全問題。分析依 OWASP Threat Modeling Process 的範圍界定、威脅辨識、緩解措施及結果評估四步進行；流程來源與限制見框架的 [威脅建模 Skill](../../skills/02_system_design/threat-modeling/SKILL.md)。

## 範圍

- 行動 App 發起授權並接收授權結果。
- 網站 API 驗證使用者及權杖，並建立網站工作階段。
- API 與內部帳戶／權杖資料服務間的查詢與更新。
- 回呼網址、授權結果傳遞、權杖保存和資源選取的邊界。

不涵蓋行動裝置作業系統、第三方服務內部實作、實際部署網路、正式資料庫結構與營運監控；這些部分缺少可公開證據。

## 概略流程

1. App 將使用者導向網站授權流程。
2. 網站驗證帳密及必要的挑戰資料，向內部資料服務查詢帳戶狀態。
3. 網站產生授權結果，可能以回應本文或受設定控制的回呼流程交回 App。
4. App 後續攜帶權杖呼叫登入交換流程。
5. 網站驗證權杖並建立網站工作階段；資源選取規則由伺服器端帳戶資料決定。

以上是靜態資料整理後的概略描述。實際 HTTP 回應、部署路由、回呼驗證、權杖政策與資源授權規則仍待系統負責人及測試環境確認。
