## 圖例與敏感資料

- 方框：外部實體；圓角方框：處理程序；圓柱：資料儲存。
- 箭頭標示資料方向與大類型，沒有代表已確認的傳輸協定或部署連線。
- 敏感資料包含帳密、授權／存取權杖、回呼參數、帳戶識別及資源識別資料。
- TB1、TB2、TB3 是建模邊界，不代表實際網路分段或防火牆規則。

# 威脅模型

## 假設與排序方式

本表為靜態證據導出的候選情境。初步優先級採低／中／高作為討論尺度，代表建議先確認的順序，不是正式嚴重度或可利用性判定。系統負責人須確認威脅是否適用、既有控制、可能性與影響。

## 威脅登錄表

| ID | DFD 元素／STRIDE | 候選攻擊情境與影響 | 初步優先級 | 建議控制與驗證 |
|---|---|---|---|---|
| TM-01 | API 與帳戶／資源關聯／E、T | 呼叫者提交的資源識別值若未由伺服器驗證其屬於已驗證帳戶，可能造成跨帳戶資料存取或錯誤工作階段關聯。靜態案例顯示資源選取可能由帳戶可用清單決定；實際授權規則仍待確認。 | 高，待核定 | 每次請求以已驗證主體在伺服器端查核資源所有權；加入跨帳戶負向測試，確認錯誤資源無法讀寫且不洩露資訊。 |
| TM-02 | App ↔ API 權杖資料流／S、I | 若權杖遭竊或可重放，攻擊者可能冒用使用者或延長未授權存取。權杖生命週期、撤銷及 App 安全儲存政策未由靜態材料完全確認。 | 高，待核定 | 確認短效期限、受眾／用途限制、刷新權杖輪替與撤銷；避免權杖進入 URL、日誌及分析事件；以重放、過期及撤銷情境驗證。 |
| TM-03 | API → App 回呼／T、I | 若回呼目的地可由請求者任意指定，或授權結果透過易記錄的 URL 參數傳遞，可能導致授權結果被導向非預期位置或出現在瀏覽器／代理日誌。 | 高，待核定 | 使用預先登錄的回呼 URI 精確比對；採用短效、一次性授權碼並以安全通道交換權杖；檢查瀏覽器歷程、Referer、代理與應用日誌是否含敏感參數。 |
| TM-04 | 帳密授權處理程序／S、D | 若登入缺少速率限制、延遲或異常行為偵測，可能遭遇密碼猜測、帳號探測或資源耗盡。相關控制在本次靜態分析範圍內尚未確認。 | 中，待核定 | 確認帳號鎖定／節流政策、錯誤訊息是否避免帳號枚舉，以及告警與復原流程；以授權測試環境驗證。 |
| TM-05 | 授權與登入流程／R | 若登入、權杖換發、撤銷及資源授權決策缺少不含秘密值的稽核紀錄，事件調查與責任追蹤可能不足。 | 中，待核定 | 記錄事件 ID、主體代碼、結果、時間及關聯追蹤 ID；不得記錄密碼或完整權杖；確認日誌完整性、存取權限及保存政策。 |

## 決策與後續

1. 先由系統負責人確認 TM-01 的伺服器端資源綁定規則。
2. 由身分／App 負責人確認 TM-02、TM-03 的權杖生命週期與回呼限制。
3. 確認速率限制、稽核紀錄與正式風險尺度後，更新優先級及控制負責人。
4. 在隔離測試環境補上負向授權、重放、回呼 URI 與日誌遮罩驗證；本 POC 沒有執行這些測試。

## 排序與剩餘風險

沿用原案例的「高／中，待核定」初步順序。公開摘要不足以獨立核定可能性與業務影響，因此不新增數值分數。改善前風險待確認；預期剩餘風險需在控制設計確定後評估；已驗證剩餘風險無證據。沒有正式風險接受紀錄，不能代填核准者。

## 模型審查與交接

結論：**證據不足**。公開模型的情境、來源限制與候選追溯可供審閱，但不足以完成正式模型／控制核准。需取得資源授權規則、Token 生命週期、回呼限制、部署與日誌設定，並確認資料用途、負責角色、期限及組織風險尺度。
