# 標準文件分類架構 (Document Taxonomy)

完整的 L1/L2 資料夾層級定義。分類時必須嚴格遵守此架構。

## 整理模式說明

根據整理的起始位置，有兩種不同的整理模式：

### 模式1：專案結構整理（從上層開始）
- **使用時機**：整理桌面、我的文件、年度資料夾等上層目錄
- **路徑格式**：
  - 專案管理類：`{年度}_{專案名}/{L1}/{L2}/`
  - 系統開發類：`{系統名稱}/{L1}/{L2}/`

### 模式2：專案資料夾整理（已在專案內）
- **使用時機**：已經在特定專案資料夾內
- **路徑格式**：直接建立 `{L1}/{L2}/`

#### 情況A：只有專案管理文件
```
{專案資料夾}/
├── 1_前置作業/
├── 2_報告書/
├── 3_簡報檔案/
├── 4_會議記錄/
├── 6_資安管理/
└── 7_行政與變更/
```

#### 情況B：包含多個系統（推薦架構）
**一個專案可能包含多個系統**，每個系統獨立建立完整的系統開發結構：

```
{專案資料夾}/
├── 1_前置作業/           ← 專案管理文件（整個專案共用）
├── 2_報告書/
├── 3_簡報檔案/
├── 4_會議記錄/
├── 6_資安管理/
├── 7_行政與變更/
│
├── {系統名稱1}/          ← 系統1（獨立的系統開發結構）
│   ├── 01_版本開發/
│   ├── 02_技術文件/
│   ├── 03_操作手冊/
│   ├── 04_測試文件/
│   └── 05_部署維運/
│
└── {系統名稱2}/          ← 系統2（獨立的系統開發結構）
    ├── 01_版本開發/
    ├── 02_技術文件/
    └── ...
```

**優點**：
- ✅ 每個系統完全獨立，容易管理
- ✅ 找某系統的文件，直接進該系統資料夾
- ✅ 符合原始設計：`{系統名稱}/{L1}/{L2}/`
- ✅ 不會混淆「這個文件是哪個系統的」

## 1. 專案管理 (Project Management)

著重於**年度專案推動、進度與合約**。這一類的文件是面向甲方或專案利害關係人的。

路徑格式：`{年度}_{專案名}/{L1}/{L2}/`

### 1_前置作業
| L2 資料夾 | 說明 | 常見檔案範例 |
|-----------|------|-------------|
| 01_報價文件 | 報價單、估價單、投標文件 | 資安檢測服務報價單、系統開發報價單 |
| 02_需求規格 | 專案需求書、RFP、需求訪談記錄 | 擴充規劃書、需求說明 |
| 03_評估報告 | 可行性評估、技術評估、成本效益分析 | 技術可行性評估報告 |

### 2_報告書
**不分 L2 子資料夾**，各類報告書（服務建議書、期初報告、期中報告、期末報告、結案報告、週報/月報等）直接放在此資料夾下。

常見檔案：服務建議書、期初報告、期中報告、期末報告、結案報告、週報/月報

### 3_簡報檔案
**不分 L2 子資料夾**，各類簡報（提案簡報、啟動會議簡報、成果展示簡報、教育訓練簡報、評選簡報等）直接放在此資料夾下。

### 4_會議記錄
| L2 資料夾 | 說明 | 常見檔案範例 |
|-----------|------|-------------|
| 01_定期會議 | 週會、月會、定期進度會議 | 週進度會議記錄 |
| 02_需求會議 | 需求訪談、需求確認會議 | MQTT資料介接需求會議記錄 |
| 03_臨時會議 | 問題處理、緊急協調、臨時召開的會議 | 效能瓶頸與擴充方案會議摘要 |

### ~~5_SDLC文件~~ **[已廢除]**

**⚠️ 此分類已廢除，請改用「系統開發/07_SDLC交付文件/」**

原因：SDLC文件雖是給甲方的交付物，但內容都是系統開發相關，為方便查找，已移至「系統開發/」下。

詳見：**系統開發 → 07_SDLC交付文件**

### 6_資安管理
資安合規相關文件，通常是交給甲方的。

| L2 資料夾 | 說明 | 常見檔案範例 |
|-----------|------|-------------|
| 01_帳號清冊 | 系統帳號管理清冊 | 帳號權限清冊 |
| 02_主機維護清冊 | 伺服器/主機清單與維護紀錄 | 主機維護清冊 |
| 03_原始碼掃描報告 | SAST/DAST掃描結果 | 原始碼弱點掃描報告 |
| 04_主機掃描報告 | 弱點掃描、滲透測試結果 | 滲透測試弱點掃描IP填寫單 |
| 05_資安通報紀錄 | 資安事件通報與處理 | 資安事件通報表 |
| 06_防火牆申請單 | 防火牆規則異動申請 | 防火牆開通申請單 |

### 7_行政與變更
| L2 資料夾 | 說明 | 常見檔案範例 |
|-----------|------|-------------|
| 01_需求變更單 | CR (Change Request) | 需求變更申請單、派工單 |
| 02_驗收確認單 | 功能簽收、驗收文件 | 功能簽收單、查核委員紀錄表 |
| 03_來往公文 | 與甲方/廠商的往來公文 | 公文影本、函覆文件 |

## 2. 系統開發 (System Development)

著重於**系統本身的生命週期與技術產出**。這一類是開發團隊內部使用的。

路徑格式：`{系統名稱}/{L1}/{L2}/`

### 01_版本開發
| L2 資料夾 | 說明 |
|-----------|------|
| 01_程式碼 | 原始碼、程式碼壓縮包 |
| 02_執行檔 | 編譯後的執行檔 |
| 03_安裝檔 | 安裝程式、setup檔 |

### 02_技術文件
| L2 資料夾 | 說明 | 常見檔案範例 |
|-----------|------|-------------|
| 01_系統架構 | 架構圖、架構說明、資料流圖 | 系統架構圖.xmind、監測數據資料流.doc |
| 02_API文件 | API規格書、介面文件 | MQTT訂閱程式開發規格.pdf、API文件.pdf |
| 03_資料庫設計 | ERD、資料表說明、欄位定義 | 欄位說明.docx、資料庫設計書.pdf |
| 04_系統設計 | 需求規格書(SRS)、系統分析、系統設計、程式規格 | 需求規格說明書.pdf、系統設計報告.docx、設計審查資料 |
| 05_參考資料 | 程式碼規範、安全指南、技術筆記、規格表 | 程式碼規範.pdf、安全編碼指南.pdf、技術參考資料 |

### 03_操作手冊
| L2 資料夾 | 說明 | 常見檔案範例 |

### 04_測試文件

| 02_測試報告 | 測試結果報告、壓力測試報告 | 測試報告.pdf、壓力測試結果.pdf |

## 3. 商務文件 (Business Documents)

報價、合約、採購等商務相關文件。
不嚴格要求 L1/L2，但建議按性質分子資料夾（如：採購/、合約/、財務/）。

---

## 4. 個人學習 (Personal Learning)

個人進修、研討會資料、學習筆記等。
按主題分子資料夾即可（如：AI學習/、技術研究/）。

---

## 5. 其他 (Others)

不屬於以上任何分類的檔案。
可按用途分子資料夾（如：工具/、暫存資料/）。

### 其他參考 (混合架構專用)
在**專案資料夾整理模式**（混合架構）中，如果發現明顯不屬於當前專案的檔案：
- 建立 `其他參考/` 資料夾
- 將這些檔案歸入此資料夾
- 由使用者後續人工判斷是否刪除或移至正確位置
- 常見情況：誤放的其他專案文件、臨時參考資料、不確定來源的檔案
