# `_WBS.md` 格式範本

放在**每個專案資料夾的最外層**，檔名 `_WBS.md`（底線開頭排在最上面）。
這是該專案的**單一真相來源**：dashboard 讀它算進度、file-organizer 照它開系統資料夾、健檢拿它當基準。

人讀得懂、Claude 也解析得了。系統清單要穩定；任務細項會隨會議變動，dashboard 執行時再從 EKB 動態補，這裡不必塞滿。

```markdown
# {專案名} 專案 WBS

- deadline: {如 2026 年底 / 過年前}
- 來源: {如 工作計畫書 7 系統}
- eip_project_id: {選填，撈 EKB 用}

| 代碼 | 系統 | 對應資料夾 | 負責人 | 備註 |
|------|------|-----------|--------|------|
| S1 | {系統名} | {資料夾名，對齊 file-organizer} | {人} | {一句話} |
| S2 | ... | ... | ... | ... |
```

規則：
- `代碼` S1、S2…固定不變（dashboard 甘特/缺漏都用它對應）
- `對應資料夾` 要跟 file-organizer 規範一致（`{系統名稱}/` 那層），這樣空資料夾＝該系統缺
- 改系統清單＝改這份；改完 dashboard 下次跑就跟著變
