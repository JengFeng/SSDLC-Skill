# EKB 會議紀錄 note 格式規則（meeting-record skill 用）

從多輪會議彙整 iteration 收斂出的完整規則。違反任一條都會被使用者打回票。

---

## 1. 標題

**格式**：`{會議正式名稱}（{YYYY-MM-DD}）— {本次重點主題}`

- ✅ `航空城進度會議（2026-05-27）— AI 預審 / 管線生成 週進度`
- ❌ `高鐵一路326號 #39 會議紀錄（2026-05-27）` — 場地不是會議名、流水號無意義
- ❌ `航空城進度會議 #39（2026-05-27）` — `#39` 沒人記得，砍掉
- ❌ `2026-05-27 航空城進度會議` — 日期不要前置

**Why**：場地是會議室地址、流水號是雞肋。重點是「會議主題 + 本次焦點」讓人一眼判斷要不要點進去看。

---

## 2. Tags

**禁止項目**：
- ❌ 日期類：`2026-05`、`2026-Q2`、`week-22`
- ❌ 流水號：`#39`、`week-22-meeting`

**允許項目**：
- ✅ 專案名：`航空城`
- ✅ 文件類型：`會議紀錄`
- ✅ 主題：`AI預審`、`管線生成`、`知識庫`、`資安`

**Why**：日期靠 `created_at` 排序就好。tag 用來分類同主題、跨時間的資料。累積一堆日期 tag 會變垃圾。

---

## 3. 與會欄

**格式**：純名單，**不加角色括號**。

- ✅ `與會：龍哥、諺庭、俊毅、家宏、tina、建成、Benson`
- ❌ `與會：龍哥（生成 API）、諺庭（管線前端）、家宏（AI 預審 / 水理 / CSV / 3D）...`

**Why**：角色已經在各議題下標「負責：XXX」，與會欄重複寫只是噪音。

---

## 4. 內容結構（依序）

### A. 會議資訊
```html
<ul>
  <li><b>日期</b>：YYYY-MM-DD</li>
  <li><b>會議名稱</b>：...</li>
  <li><b>地點</b>：...（可省）</li>
  <li><b>主題</b>：...</li>
  <li><b>與會</b>：純名單</li>
</ul>
```

### A2. ★ 上次事項追蹤表（系列會議的第 2 次起，必加）

**會議是一條系列（#39 → #43 → 下次），不是一次性事件。上次的「必交清單／延後議題」就是這次的「追蹤事項」，沒做完的要 roll-forward 一路追到 closed。**

放在「會議資訊」之後、各議題之前，當第一個 `<h2>`：

```html
<hr>
<h2>① 上次會議（#XX / 日期）事項追蹤</h2>
<p style="color:#666;font-size:0.9em;">上次必交／延後事項在本次的進度；未完成者已滾入文末「下次必交」續追。<a href="note.php?id={上次note_id}">→ #XX 會議紀錄</a></p>
<table border="1" cellpadding="6" cellspacing="0" style="border-collapse:collapse;width:100%;font-size:14px;">
<tr style="background:#f4f4f4;"><th>負責</th><th>上次事項</th><th>狀態</th><th>本次進展</th></tr>
<!-- 每列：上次必交/延後的一項 → 對照本次逐字稿判斷狀態 -->
</table>
```

**狀態四態**（用色票 badge，不用 emoji）：
- `完成` 綠 bg `#d4edda` / fg `#1a7a3a`
- `進行中` 藍 bg `#cfe2ff` / fg `#0a4fa0`
- `本次未動` 紅 bg `#f8d7da` / fg `#a01722`
- `續追` 紫 bg `#e7d6f5` / fg `#6b3fa0`

**做法**：
1. 先讀「上次 note」的「必交清單（依負責人）」+「延後議題」
2. 對照「本次逐字稿」，逐項判斷狀態 + 寫「本次進展」（誠實：沒談到就標『本次未動』，別硬說有進展）
3. **roll-forward**：狀態為 進行中／未動／續追 的項目，自動帶進本次文末「下次必交」，這樣同一件沒做完的事會一路被追到完成、不會斷掉
4. 用 `<a href="note.php?id=XX">` 串回上一份紀錄，形成系列

**Why**：使用者打開這次紀錄，第一眼就要看到「上次講的做了沒」。沒有這張表，會議紀錄變成一盤散沙、無法追蹤承諾。

### B. 各議題（一、二、三...）

每個議題下面再分子議題（1.1 / 1.2 / ...）。

每個子議題**必含**：
```html
<h3>議題 X.Y 標題</h3>
<ul>
  <li><b>現況</b>：...</li>
  <li><b>決議</b>：...</li>
  <li><b>負責</b>：XXX</li>
</ul>
```

可選欄位：
- `<li><b>原因</b>：...</li>` — 為什麼這樣決議（脈絡）
- `<li><b>狀態</b>：...</li>` — 進行中 / 已完成 / 延後

### C. 下次會議區塊（最後）

分兩塊：

```html
<h2>★ 下次會議</h2>

<h3>A. 必交清單（依負責人）</h3>
<ol>
  <li><b>{負責人}</b>
    <ul>
      <li>{交付項目 1}</li>
      <li>{交付項目 2}</li>
    </ul>
  </li>
  ...
</ol>

<h3>B. 延後到下次討論的議題</h3>
<ul>
  <li><b>{議題標題}</b>（議題編號）— {延後原因 / 等什麼}</li>
  ...
</ul>
```

## 5. 重點標色（inline style）

- **紅** `color:#c00` — 卡關、阻塞、紅燈警報
- **藍** `color:#0066cc` — 重大決議、本次重要變更
- **紫** `color:#9333ea` — 待 Benson 跨議題決策、延後等使用者想清楚

**Why**：純黑文字會讓重點失焦。三種顏色精準標示，使用者掃一眼就抓得到關鍵。

純條列待辦不標色（會稀釋）。

---

## 6. ⚠️ 禁止做的事

### A. 不要寫「責任分派總表」
（依負責人 aggregate 列任務全貌的大表）

**Why**：那是「PM dashboard」範疇。會議紀錄是 per-meeting 事件，不該扮演 PM 工具。即使 PM 系統還沒做，會議紀錄也不能代打。

各議題的「負責：XXX」OK 留、「下次必交清單」OK 留（因限定下次會議前範圍），但不要全局 by-person 總表。

### B. 不要寫頁尾自我交代

❌ 例：
```
原始逐字稿（語音轉文字未校正版）：見附件「XXX.md」

備註：本份彙整已對原始逐字稿的語音轉文字錯字做人工校正（「預神」→「預審」...）。
```

**Why**：附件已掛 EKB attached_files 區、讀者自己看得到；錯字校正對照是工作筆記不是讀者價值。會增加噪音。

### C. 標題不要日期前置 + 不要場地名 + 不要流水號

見上 §1。

### D. Tags 不要放日期

見上 §2。

## 7. EKB API 呼叫

```
POST /api/notes.php
Body:
{
  "title": "...",
  "content": "<HTML>",
  "eip_project_id": <int>,
  "tags": ["航空城", "會議紀錄", ...],
  "source_ref": "🎙️ 會議逐字稿：{會議名} {YYYY-MM-DD} ({原逐字稿檔名})",
  "change_reason": "建立 YYYY-MM-DD 會議紀錄"
}
```

**注意事項**：
- `source` 欄位有 enum 限制，**不要塞自己 string**（會 truncated 報錯）。來源描述放 `source_ref`。
- ★ **`source_ref`「來源」慣例**：會議紀錄一律用 `🎙️ 會議逐字稿：{會議名} {日期} ({原檔名})` 格式，讓人在 note.php「📥 來源」欄一眼知道這篇從哪場會議的逐字稿來的。（EKB 全站來源前綴慣例：💬LINE / 🎙️會議 / 🤖AI / 📎檔案 / 📺YouTube / 🔗網頁 / 📚Wiki / 📧Email / ✍️手動，詳見 EKBSpec）
- `eip_project_id` 整數，先 `GET /api/projects.php` 拿可選清單給 user 挑。
- 修改 note 用 `PATCH /api/notes.php?id={id}`，**一定要帶 `change_reason`**。
- 加附件用 `POST /api/notes.php?id={id}&op=attach_file`，body `{file_id, relation: 'attachment'|'source', append_to_content: true}`。
- 圖片需 inline 顯示：上傳的 mime 若被偵測成 octet-stream，需手動把 content 內的 `<a class="ekb-attachment">` 改成 `<img>`。
