# Quote Builder Skill

把工項清單轉成標準格式的 .xlsx 報價單。

## 何時啟用

觸發詞：估價、報價、報價單、經費概算、人月、給主管的報價、估算費用、單價、拆工項

典型情境：
- 已有工項清單（5 大模組 × N 子項），要估錢給主管 / 業主
- 已有預算上限（例如 150-200 萬），要反推合理單價組合
- 提案／投標前要附經費概算表

## 格式選擇（先分流）

報價有兩種版型，**動工前先判斷要哪一種**：

| 格式 | 用途 | 產生器 | 加成結構 |
|---|---|---|---|
| **政府案 經費明細表** | 政府標案經費概算、投標附件 | `scripts/build_quote.py` | 合計＋廠商管理費5%＋營業稅5% |
| **FIT 公司專用報價單** | 對外以「準線智慧科技」名義出的商業報價 | `scripts/build_fit_quote.py` | 小計＋稅額5%（**無管理費**） |

判斷：
- 客戶是**政府機關**、要塞進標案文件 → 政府案格式
- 客戶是**民間公司 / 工程行 / 設計公司**、要公司抬頭與業務窗口、客戶簽回用印 → FIT 格式
- 不確定就問使用者「這份對外掛誰的抬頭？」

FIT 格式的 config 結構、欄位、公司固定資訊見 [references/fit_format.md](references/fit_format.md)。
以下「標準工作流」Step 1–4（盤點輸入、定單價、雲端租賃）兩種格式通用，Step 5 依格式換對應產生器。

## 標準工作流

### Step 1：盤點輸入

跟使用者確認四件事：

1. **工項清單**：5 大模組？每模組幾個子項？各約幾人月？
2. **人月費率（單價）**：🚨 **一定要主動問使用者**「一個人月抓多少？」（例：「一個月人力 70,000」）。
   這個數字定下來後**全案固定**，當作「單價」欄的值，不再逐行變動。使用者沒講就問，不要自己猜一個。
3. **預算範圍**：天花板多少？落在哪個區間？（影響人月數怎麼配，不是影響單價）
4. **是否含 AI 服務**：有 LLM / GPU / ASR / 向量 DB → 必須另列雲端租賃 OPEX

> 釘死單價後，報價只剩一個變數：每行估幾個人月。總價＝人月數×固定費率，所有數字都追溯得回去。

### Step 2：選排版風格

| 風格 | 適用 | 行數 |
|---|---|---|
| **精簡版** | 給主管快看、業主初次溝通 | 5-7 行（一個模組一行，細節寫備註） |
| **詳細版** | 招標附件、SDLC 經費明細 | 28+ 行（每子項獨立一行 + 模組小計） |

**預設精簡版**。使用者明確要展開才用詳細版。

### Step 3：定單價

詳見 [references/rate_card.md](references/rate_card.md)。

> 🚨 **第一鐵律 — 單價必須可追溯，不准湊金額**
>
> 「單價」欄填的**永遠是固定費率**（人月費率 或 人日費率），**不是湊出來的總價**。
> 同一個角色／同一案的單價**從頭到尾不變**，會變的是「數量」（人月／人日數）。
>
> - ✔ 對：單位=月、單價=70,000（固定）、數量=0.5 / 0.9 / 0.35…（每行不同）→ 總價=數量×單價
> - ✘ 錯：單位=式、數量=1、單價=35,000 / 62,000 / 27,500…（每行亂跳）
>
> 為什麼：業主／審查委員看到單價每行不一樣，第一句就是「這 62,000 怎麼算的」。
> 答不出「費率×人月」的追溯鏈 = 整張報價被質疑。**「式 × 1 × 任意金額」是被退件的頭號寫法。**
>
> 例外：不同**角色**本來就不同費率（PG／SA／CV 各有各的費率）。
> 「分角色 → 各角色一個固定費率」OK；「同角色卻每行跳價」不行。

定費率三鐵律：

1. **AI 工程師單價 ≥ 後端工程師 1.5 倍**：CV 7-10萬、LLM/RAG 9-12萬，PG 5-8萬
2. **政府小案天花板 5-7 萬／人月**：超過業主會打槍；策略性卡位案才壓 5 萬
3. **市場合理 8-12 萬／人月起跳**：商業案、企業 POC、AI 案

**單一費率 vs 分角色費率 — 怎麼選：**

| 情境 | 寫法 | 單位 / 單價 / 數量 |
|---|---|---|
| 單一性質的案（純開發、無 AI） | 一個固定人月費率打全案 | 月 / 固定（如 70,000）/ 各行人月數 |
| 多模組商業案（含 AI） | 每模組對應一個主導角色的費率 | 月 / 該角色費率 / 各模組人月數 |

兩種都一樣：**數量才是估出來的變數，單價是查表得來的固定值**。先估「這行要幾個人月」，再乘固定費率，**絕不可反過來先想總價再回填單價**。

### Step 4：判斷是否要加雲端租賃

若工項含以下任一，**必須另列「雲端 AI 服務租賃 (首年)」**：

- LLM API 推論（RAG、對話、自動風險評估）
- GPU 推論（CNN、YOLO、SAM、ResNet 等）
- ASR / TTS（Google / Azure / Whisper API）
- 向量資料庫 hosting（Pinecone / Qdrant Cloud）
- 雲端 VM + 物件儲存

預設組合（單田場、1 年）：總約 20 萬／年。詳見 [references/cloud_rental.md](references/cloud_rental.md)。

### Step 5：跑產生器

```bash
python ~/.claude/skills/quote-builder/scripts/build_quote.py \
  --output "<目標檔名>.xlsx" \
  --client "桃園市政府" \
  --project "「XX 系統」" \
  --config items.json
```

`items.json` 格式範例見 [references/config_schema.md](references/config_schema.md)。

或直接 import script 的 `build_quote()` 函式自行傳入 list。

### Step 6：驗算 + 報告

腳本會印出：
```
合計 = 1,805,000
+管理費 5% = 90,250
+營業稅 5% = 94,762
總計 = 1,990,012
```

對照 Step 1 的預算區間，超出就回頭調單價或人月。

## 結構固定不變

每份報價的 row 順序：

```
標題列 1：客戶機關名稱
標題列 2：「專案名稱」
標題列 3：經費明細表
表頭：編號 / 內容 / 單位 / 數量 / 單價 / 總價 / 備註
工項 1
工項 2
...
工項 N
合計
廠商管理費用利潤(約5%)
營業稅5%
總計
```

> **不要新增 PM、SA、QA 行**：原始參考案沒有這幾個角色。要列管理費就用「廠商管理費 5%」吸收。

## 反模式（不要做）

- **不要**用「式 × 數量1 × 任意金額」當工項列 → 單價變成湊出來的，業主問「這金額怎麼算的」答不出來
- **不要**讓同一案的單價每行跳來跳去（35,000 / 62,000 / 27,500…）→ 單價是固定費率，會動的是數量（人月）
- **不要**統一單價 5 萬／人月套用到 AI 工程師 → 賠錢
- **不要**把 LLM/GPU 當開發費塞進人月 → 沒算到持續燒的 token / GPU 算力
- **不要**詳細版 28 項展開後就不做精簡版 → 主管看不下去
- **不要**自己加 PM/SA/QA 行（除非使用者明確要求）→ 跑掉原本格式
- **不要**用現代風格排版（粗框、彩色 banner）→ 政府案要素樸
