# SA 方法論：從雛形／需求 → SA 系統分析設計

> 系統化的推導步驟。SKILL.md 的 SOP 是骨架，這裡是每步的「怎麼想」。

---

## Step 0 — 抽素材

### A. 從雛形 HTML 抽（核心特色：接 bootstrap-ui）

| 雛形元素 | 推出什麼 |
|---|---|
| `<form>` 的 input/select/textarea | 候選**欄位**（`name`/`label`→欄位名，`type`/`maxlength`→型別與長度線索，`required`→必填） |
| `<table>` 的 `<th>` | 一個**實體**的欄位集；整張 table = 一個實體 |
| 清單／卡片重複結構 | **實體集合**（一對多的「多」端） |
| 按鈕（新增/編輯/刪除/查詢/匯出/審核/上傳） | **API 操作**（CRUD + 業務動作） |
| 下拉固定選項 | **列舉欄位** 或 **字典表(lookup)** |
| 頁面層級／主檔-明細 | **實體關聯**（主表 1:N 明細表） |
| 搜尋/篩選欄位 | API 的**查詢參數** + 該欄位常建**索引** |

### B. 從需求文字抽

- **名詞** → 實體 / 屬性（「會員有多筆訂單」→ 會員、訂單）
- **動詞** → 操作 / API（「審核申請」→ `PUT /applications/{id}/approve`）
- **數量詞** → 關聯基數（「一張訂單含多個品項」→ 1:N）
- **限制詞** → 欄位約束（「身分證必填且唯一」→ NOT NULL + UNIQUE）

## Step 1 — ER Model（先做，其他都靠它）

1. **找實體**：強實體（會員、訂單）vs 弱實體（依附主檔的明細）。
2. **定屬性**：PK（建議每表 `id` 流水號 PK）、一般屬性；衍生屬性（如年齡、總計）**別存**，由程式算。
3. **關聯與基數**：
   - **1:1 → 一律併回主表**（除非有強隔離理由：超大文字／二進位欄位、權限分離，才另拆）
   - 1:N（最常見，N 端放 FK）
   - **M:N → 一定拆關聯表**（中間表放兩邊 FK，可帶關聯屬性）
   - ★**別過度拆表**：只有真正 1:N／M:N 才獨立成表；1:1 的單值屬性留在主表，別為了好看拆出一堆只有 1~2 欄、跟主表 1:1 的碎表。**寧可主表欄位多，也不要碎表滿天飛。**（枚舉／受控清單用字典表 OK）
4. **正規化到 3NF**：去除重複群、部分依賴、傳遞依賴；為效能可適度反正規化，但**要在資料字典標註原因**。
5. **慣例欄位**：每表加 `id`(PK)、`create_time`、`update_time`；軟刪用 `is_deleted` BIT；需要稽核加 `created_by`/`updated_by`。

---

## Step 2 — 資料字典（ER 的細節版）

每實體每欄位逐列定義：**欄位名 / 中文說明 / 型別 / 長度 / PK·FK / 必填 / 預設 / 驗證規則 / 備註**。
型別對應 MS SQL Server（Benson 主力，對照表見 `output-templates.md`）。
重點：FK 欄位要標「→ 對應哪張表的哪個欄位」；驗證規則要可執行（格式、範圍、唯一）。

---

## Step 3 — 系統架構圖

1. **分層**（由上而下）：
   - 表現層：Bootstrap Web / Flutter App / PWA
   - API 層：REST API（.NET Core 主力 / Node / PHP）
   - 業務服務層：核心邏輯、排程、通知
   - 資料層：MS SQL Server（＋ NAS 檔案儲存）
2. **橫向關注**（標在側）：認證授權、log/稽核、快取、排程、檔案儲存。
3. **外部介接**（Benson 領域常見）：LINE Bot 推播、IoT/MQTT 感測器、GIS 圖台(Easymap/OpenLayers)、CCTV 影像、第三方/政府 API。
4. **部署**：Benson 慣例 **HA 主備援分流、VM 虛擬化**；明確標**單點風險**（SPOF）與備援策略。
5. 用 mermaid `flowchart TD` + `subgraph` 分層畫（範本見 `mermaid-patterns.md`）。

---

## Step 4 — API spec

1. **RESTful 慣例**：資源名複數、HTTP 動詞表操作、層級用路徑（`/orders/{id}/items`）。
2. **每實體標準 CRUD**：
   - `GET /resources`（列表，含分頁/篩選）
   - `GET /resources/{id}`（單筆）
   - `POST /resources`（新增）
   - `PUT /resources/{id}`（更新）
   - `DELETE /resources/{id}`（刪除，多用軟刪）
3. **業務操作**（非 CRUD）：用子資源或動作路徑（`POST /applications/{id}/approve`）。
4. **每端點定義**：方法 / 路徑 / 說明 / 請求參數 / 回傳結構 / 狀態碼 / 認證。
5. **慣例**：版本 `/api/v1/`、分頁 `?page=&size=`、統一回傳 `{code,message,data}`、認證 `Bearer token`。
