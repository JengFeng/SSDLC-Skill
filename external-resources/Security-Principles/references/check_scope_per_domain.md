# 每構面比對範圍定義 — @security-check 執行參照

> 本文件定義 AI 代理執行 `@security-check` 時，每個安全構面的具體比對對象、比對方式與判定基準。
> AI 代理在第 3 步「逐項比對」時必須參照本文件，不得遺漏或自行擴大範圍。

---

## 通用規則

1. **比對基準**：以 `assets/checklist_*.md` 中各等級的控制措施項目為比對基準
2. **比對方式**：存在性檢查（是否存在該機制）為主，正確性檢查（機制是否正確實作）為輔
3. **判定標準**：
   - ✅ 符合：系統產出中存在對應機制，且實作符合控制措施要求
   - ❌ 不符合：系統產出中缺少該機制，或機制實作不符合控制措施要求
   - ➖ 不適用：該控制措施在當前專案類型或階段中無意義
   - ⬚ 未涵蓋：該控制措施需在後續階段才能驗證（如部署階段的憑證配置）
4. **佐證說明**：每項不符合或部分符合的項目，必須標註具體比對的檔案路徑或產出物

## 構面 1：存取控制

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| 帳號管理 | 程式碼中的使用者帳號 CRUD 邏輯、資料庫使用者管理表 | 存在性 + 正確性 |
| 最小權限 | API 路由的權限 middleware、資料庫連線帳號權限、檔案系統存取權限 | 存在性 |
| 遠端存取 | API 認證機制（JWT/OAuth/Session）、CORS 設定、SSH/遠端連線設定 | 存在性 |

### 具體檢查項目

1. 是否有帳號管理機制（申請、建立、修改、停用、刪除程序）
2. 是否有最小權限原則實作（程式碼中是否有角色/權限控制邏輯）
3. 是否有遠端存取授權與監控機制
4. 臨時或緊急帳號是否有過期停用機制
5. 閒置帳號是否有自動禁用機制

## 構面 2：事件日誌與可歸責性

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| 記錄事件 | 程式碼中的 logging 機制、日誌模組設定 | 存在性 + 正確性 |
| 日誌格式 | 日誌輸出格式（是否含事件類型、時間、位置、使用者） | 正確性 |
| 校時 | NTP 設定、伺服器時間同步配置 | 存在性 |
| 日誌保護 | 日誌檔案存取權限、日誌伺服器連線設定 | 存在性 |

### 具體檢查項目

1. 是否有日誌記錄機制（程式碼中有 logging/import log 相關模組）
2. 日誌是否包含必要欄位（事件類型、時間戳記、使用者身分、IP 位址）
3. 是否有日誌留存政策定義（至少 6 個月）
4. 日誌處理失效時是否有回應機制
5. 時戳是否可對應 UTC/GMT，是否有 NTP 同步設定
6. 日誌存取是否有權限控制

## 構面 3：營運持續計畫

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| 資料備份 | 備份腳本、備份排程設定、備份還原測試紀錄 | 存在性 |
| 系統備援 | 備援架構設計文件、容錯機制設定 | 存在性 |
| RPO/RTO | 災備復原計畫文件、可容忍損失時間定義 | 存在性 |

### 具體檢查項目

1. 是否有資料備份腳本或設定（`backup.sh`、`docker volume` 備份、DB dump 腳本）
2. 是否定義了 RPO（資料可容忍損失時間）
3. 是否有備份還原測試紀錄
4. 是否有系統備援架構設計（如多副本、Failover）

## 構面 4：識別與鑑別

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| 身分驗證 | 登入模組、Session 管理、Token 驗證邏輯 | 存在性 + 正確性 |
| 密碼策略 | 密碼複雜度檢查、Hash 演算法、鹽值使用 | 正確性 |
| 多因子認證 | MFA/2FA 機制設定 | 存在性 |
| Session 管理 | Session 逾時設定、Session 固定防護 | 存在性 + 正確性 |

### 具體檢查項目

1. 是否有身分驗證機制（登入/登出功能）
2. 密碼是否使用安全 Hash 演算法（bcrypt/scrypt/Argon2，**不得**使用 MD5/SHA1）
3. 密碼是否有複雜度要求（長度、字元組合）
4. 是否有 Session 逾時與自動登出機制
5. 是否有多因子認證機制（可選，視等級要求）

## 構面 5：系統與服務獲得

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| SSDLC 流程 | 階段產出物（SKILL.md、traceability_matrix.md） | 存在性 |
| 威脅建模 | 威脅模型文件、STRIDE 分析產出 | 存在性 |
| OWASP 對應 | 安全掃描報告、OWASP Top 10 檢核紀錄 | 存在性 |
| SBOM | 軟體物料清單（`outputs/sbom.json`） | 存在性 |
| 供應鏈安全 | 第三方套件版本、已知漏洞掃描結果 | 存在性 |

### 具體檢查項目

1. 是否遵循 SSDLC 開發流程（有階段產出物）
2. 是否有威脅建模產出（STRIDE / PASTA）
3. 是否有 OWASP Top 10 安全掃描紀錄
4. 是否有 SBOM（Software Bill of Materials）
5. 第三方依賴是否有已知漏洞掃描（`npm audit`、`pip audit`、`OWASP Dependency Check`）

## 構面 6：系統與通訊保護

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| TLS/HTTPS | Web 伺服器設定（Nginx/Apache/IIS）、SSL 憑證配置 | 存在性 + 正確性 |
| 憑證管理 | 憑證到期日、憑證自動更新機制 | 正確性 |
| 資料加密 | 敏感資料加密邏輯（傳輸中 + 靜態儲存） | 存在性 |
| CORS | 跨來源資源共享設定（`Access-Control-Allow-Origin`） | 正確性 |

### 具體檢查項目

1. 是否啟用 HTTPS（TLS 1.2+）
2. SSL 憑證是否有效且未過期
3. 敏感資料（密碼、Token、個資）是否有加密儲存
4. API 回應是否避免洩漏敏感資訊（Error handling 中不含堆疊追蹤）
5. CORS 設定是否限制允許來源

---

## 構面 7：系統與資訊完整性

### 比對對象

| 控制措施類別 | 檢查標的 | 比對方式 |
|:------------|:---------|:---------|
| 漏洞修復 | 安全掃描報告、漏洞修復紀錄 | 存在性 |
| 系統監控 | 監控設定（Prometheus/Grafana/Sentry）、Alert 規則 | 存在性 |
| 輸入驗證 | 程式碼中的輸入清理、SQL injection 防護、XSS 防護 | 存在性 + 正確性 |
| 完整性校驗 | SHA-256 簽章機制、檔案完整性檢查 | 存在性 |

### 具體檢查項目

1. 是否有安全掃描報告（靜態/動態分析）
2. 是否有系統監控與告警機制
3. 使用者輸入是否有清理/驗證（防 SQL injection、XSS）
4. 是否有部署完整性校驗機制（SHA-256 簽章）

## 構面 8：組織、實體與供應鏈安全（非軟體因子）

### 處理原則

> ⚠️ **本構面為「非軟體開發範疇」的安全因子**，在 SSDLC 軟體開發專案中預設標記為 ➖ 不適用。

### 比對對象

| 控制措施類別 | 檢查標的 | 處理方式 |
|:------------|:---------|:---------|
| 人力安全 | 人員安全查核、在職訓練 | ➖ 不適用（屬組織管理面） |
| 證照管理 | 資安證照維護 | ➖ 不適用（屬組織管理面） |
| 機房實體安全 | 門禁、監控、環境控制 | ➖ 不適用（屬實體管控面） |
| 供應鏈管理 | 供應商評鑑、SLA | ⚠️ 視專案需求（若涉及外部 API 服務商則檢查） |

### 檢核報告處理

1. 構面 8 在報告中獨立成章：`## 構面 8：組織、實體與供應鏈安全（非軟體因子）`
2. 每項控制措施標記為 ➖ 不適用，並加註「非軟體開發範疇，屬組織/實體管控」
3. 僅當專案明確涉及外部服務商整合時，才對「供應鏈管理」子類別進行存在性檢查
4. 在「階段性限制說明」章節中統一註明：「構面 8 全部控制措施屬非軟體因子，不列入軟體開發專案之符合性判定」
